# Боевой базаға жаңарту

Толық SQL: `outputs/prod-db/20261020-production-update.sql`.

Боевой Supabase жобасы: **tgiwtfavkuphllpgtuck**. Тест жобасы: **bfssfdstlobqsedizhiv**. Боевой SQL-ды осы екі жобаны тексеріп барып орындаңыз.

1. Боевой Supabase → SQL Editor → New query ашыңыз.
2. SQL файлын толық көшіріп, бір рет Run басыңыз. Ол бір транзакциямен орындалады және қайта орындауға болады.
3. pg_cron кеңейтіміне рұқсат қатесі шықса, Database → Extensions ішінен pg_cron қосып, файлды қайта толық орындаңыз.
4. Соңғы нәтижеде `monthly-debt-opening` тапсырмасы `active = true`, ал екі функцияның атауы бос емес болуы керек.
5. Сайтта ай бойынша қарыз есебін және админ/менеджердің «Ай басындағы қарыз» түзетуін тексеріңіз.

Өзгерістер:

- `payments.id` генераторы жоқ болса қалпына келеді; `created_at`, `paid_at`, `note` әдепкі мәндері орнатылады.
- `monthly_opening_debts` кестесі жоқ болса жасалады. Кредит лимиті, жабылған ай төлемінің жиыны, бастапқы қарыз түзетуі, түзеткен қолданушы UUID-і және уақыты сақталады.
- Жаңа ай Алматы уақытымен 00:00-де күнделікті жоспарлаушы арқылы ашылады; сайт сұрауы өткізіліп кеткен айларды да толықтырады.
- `monthly_debt_report` таңдалған айдың есебін береді. Ағымдағы қарыз карточкадағы және кредит тексерісіндегі есеппен бірдей.
- `set_month_opening_debt` ағымдағы бастапқы қарызды рұқсаты бар админ/менеджерге өзгертуге мүмкіндік береді. Айырмасы нақты қарызға бір транзакциямен қосылады; өткен айдың жабылған қарызы сақталады.
- Тапсырыстар тарихының ай/жыл сүзгісі мен карточкалардың көрінісі — сайт кодындағы өзгерістер, қосымша SQL қажет емес.

Бұл файл пайдаланушыларды көшірмейді және Auth аккаунттарын өзгертпейді. Боевойда `admin-users` функциясы жұмыс істеп тұрса, оны қайта жариялау қажет емес; тест жобасындағы жетіспейтін функция бөлек жарияланды. Боевой базаға бұл сессияда SQL автоматты жіберілген жоқ.

Тексеру командалары:

```sh
npm test
npm run build -- --configuration development
```

SQL регрессиялары (`supabase/tests/monthly_debt_rollover.sql`, `supabase/tests/edit_month_opening_debt.sql`) тек миграциялар қолданылған тест базасына арналған. Олар боевой скриптке кірмейді.

Осы нұсқа жергілікті PGlite PostgreSQL ортасында тексерілді: алғашқы орындау, қайта орындау, өткізіліп кеткен айлар, төлем/қарыз есебі және рұқсат тексерістері өтті. Бұл тексеруде Supabase Auth схемасы мен pg_cron жоспарлаушысы тест үлгісімен алмастырылды; нақты pg_cron іске қосылуы боевойда файлдың соңғы сұрауымен тексеріледі. Қайталау үшін бөлек уақытша каталогқа `@electric-sql/pglite` орнатып, `PGLITE_MODULE` айнымалысына оның `dist/index.js` жолын беріп, `node scripts/verify-production-sql.mjs` іске қосуға болады.

SQL файлын миграциялардан қайта жинау:

```sh
node scripts/build-production-sql.mjs
```
